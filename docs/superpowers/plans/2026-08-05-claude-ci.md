# Claude-Integrated CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a lean lint+types CI workflow and three on-demand Claude workflows to the `kumarsaroj18/plane` fork, so arbitrary prompts can be run against the project from GitHub Actions.

**Architecture:** Four independent workflow files, one per trigger. Permissions are scoped per file: deliberate triggers (manual dispatch, `@claude` mention) get `contents: write`; the automatic PR review gets `contents: read` plus a read-only tool allowlist. Prompts live as versioned markdown in `.github/prompts/` and are selected by a dispatch dropdown or overridden by free text.

**Tech Stack:** GitHub Actions, `anthropics/claude-code-action@v1`, pnpm 11 + turbo, Node 22.18.0, oxlint, actionlint.

## Global Constraints

- Branch: `feat/workshop`. Never commit to `preview`.
- Node version is **22.18.0** exactly (from `.mise.toml`). Pin it explicitly in every `setup-node` step.
- Package manager is pnpm via corepack. Always `pnpm install --frozen-lockfile`.
- Pin the action as `anthropics/claude-code-action@v1`.
- Auth is `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}`. Never `anthropic_api_key`.
- Every Claude job needs `id-token: write` in addition to its other permissions.
- Every job sets `timeout-minutes` and every workflow sets a `concurrency` group with `cancel-in-progress: true`.
- The nine inherited upstream workflows are never modified or deleted.
- Never interpolate `${{ inputs.* }}` directly inside a `run:` block. Bind it to `env:` first — direct interpolation is a script-injection vector.
- The tool flag inside `claude_args` is `--allowedTools`, camelCase.

## File Structure

| File | Responsibility |
|---|---|
| `.github/workflows/ci.yml` | Lint and type-check changed packages on PRs into `preview` |
| `.github/workflows/claude-dispatch.yml` | Manual prompt runner; resolves a prompt from library or free text |
| `.github/workflows/claude-mention.yml` | Responds to `@claude` in issue and PR comments |
| `.github/workflows/claude-review.yml` | Automatic read-only review on every PR |
| `.github/prompts/code-review.md` | Prompt: general code review |
| `.github/prompts/security-audit.md` | Prompt: security audit |
| `.github/prompts/i18n-drift.md` | Prompt: locale key drift |
| `.github/prompts/dependency-audit.md` | Prompt: dependency health |
| `.github/prompts/test-coverage-gaps.md` | Prompt: untested surface area |
| `.github/workflows/README.md` | Explains each workflow and how to run it |

## How verification works here

These are YAML workflows, not library code, so the test cycle is not pytest. Each task uses a two-stage loop:

1. **Static:** `actionlint` on the file. Catches YAML errors, bad expressions, invalid `needs`/`if` references, and shellcheck issues inside `run:` blocks.
2. **Live:** trigger the workflow on GitHub and observe the run reach `completed / success` via `gh run watch`.

A task is done only when stage 2 is green. A workflow that lints but has never run is not done.

```yaml
name: CI

on:
  pull_request:
    branches: [preview]
    types: [opened, synchronize, reopened, ready_for_review]
  workflow_dispatch:

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

env:
  NODE_VERSION: "22.18.0"

jobs:
  lint:
    name: Lint (oxlint)
    runs-on: ubuntu-latest
    timeout-minutes: 10
    env:
      TURBO_SCM_BASE: ${{ github.event.pull_request.base.sha }}
      TURBO_SCM_HEAD: ${{ github.sha }}
    steps:
      - name: Checkout
        uses: actions/checkout@v6
        with:
          fetch-depth: 50
          filter: blob:none

      - name: Set up Node
        uses: actions/setup-node@v6
        with:
          node-version: ${{ env.NODE_VERSION }}

      - name: Enable pnpm
        run: corepack enable pnpm

      - name: Resolve pnpm store path
        run: echo "STORE_PATH=$(pnpm store path --silent)" >> "$GITHUB_ENV"

      - name: Cache pnpm store
        uses: actions/cache@v5
        with:
          path: ${{ env.STORE_PATH }}
          key: pnpm-store-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-store-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      # --affected needs a base ref to diff against. On workflow_dispatch there is
      # no pull_request payload, so TURBO_SCM_BASE is empty and we check everything.
      - name: Run oxlint
        run: |
          if [ -n "${TURBO_SCM_BASE}" ]; then
            pnpm turbo run check:lint --affected
          else
            pnpm turbo run check:lint
          fi

  types:
    name: Type check (tsc)
    runs-on: ubuntu-latest
    timeout-minutes: 20
    env:
      TURBO_SCM_BASE: ${{ github.event.pull_request.base.sha }}
      TURBO_SCM_HEAD: ${{ github.sha }}
      NODE_OPTIONS: "--max-old-space-size=4096"
    steps:
      - name: Checkout
        uses: actions/checkout@v6
        with:
          fetch-depth: 50
          filter: blob:none

      - name: Set up Node
        uses: actions/setup-node@v6
        with:
          node-version: ${{ env.NODE_VERSION }}

      - name: Enable pnpm
        run: corepack enable pnpm

      - name: Resolve pnpm store path
        run: echo "STORE_PATH=$(pnpm store path --silent)" >> "$GITHUB_ENV"

      - name: Cache pnpm store
        uses: actions/cache@v5
        with:
          path: ${{ env.STORE_PATH }}
          key: pnpm-store-${{ runner.os }}-${{ hashFiles('**/pnpm-lock.yaml') }}
          restore-keys: |
            pnpm-store-${{ runner.os }}-

      # check:types declares dependsOn ["^build"] in turbo.json, so turbo builds
      # dependency packages itself. Caching .turbo is what makes that affordable.
      - name: Cache turbo
        uses: actions/cache@v5
        with:
          path: .turbo
          key: turbo-${{ runner.os }}-${{ github.sha }}
          restore-keys: |
            turbo-${{ runner.os }}-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run tsc
        run: |
          if [ -n "${TURBO_SCM_BASE}" ]; then
            pnpm turbo run check:types --affected
          else
            pnpm turbo run check:types
          fi
```

`.github/prompts/security-audit.md`:

```markdown
Audit this repository for security problems.

Scope your attention to application code under `apps/` and `packages/`. This is a
fork of Plane, an open-source project management tool with a Django API in
`apps/api` and React apps in `apps/web`, `apps/admin`, and `apps/space`.

Look for:

1. Secrets or credentials committed to the repository.
2. Injection risks — SQL, command, or template injection, especially in `apps/api`.
3. Authentication and authorization gaps in Django views and DRF permissions.
4. Unsafe deserialization or unvalidated user input reaching a sink.
5. Cross-site scripting risks in React code, especially `dangerouslySetInnerHTML`.
6. Overly permissive CORS or cookie settings.

For each finding, give the file path, line number, the attack scenario in concrete
terms, and a fix. Do not report theoretical issues with no reachable path. Rank
findings most severe first.
```

`.github/prompts/i18n-drift.md`:

```markdown
Check for translation key drift in `packages/i18n/src/locales`.

Treat the English locale as the source of truth.

Report:

1. Keys present in English but missing from other locales.
2. Keys present in other locales but absent from English, which are likely stale.
3. Keys whose placeholders or interpolation tags differ between English and a
   translation, since these break at runtime.
4. Entries that appear untranslated — a non-English locale whose value is byte

Present the result as a table of locale, key, and problem type. Summarize the
per-locale totals first so the scale of drift is clear before the detail.

Do not edit any locale files. Report only.
```

`.github/prompts/dependency-audit.md`:

```markdown
Audit dependency health for this monorepo.

The workspace is pnpm with a catalog in `pnpm-workspace.yaml`. External dependencies
use `catalog:` and internal packages use `workspace:*`, per `AGENTS.md`.

Report:

1. Dependencies declared directly with a version range where a `catalog:` entry
   already exists, since these bypass the catalog and cause version skew.
2. The same external dependency pinned to different versions across packages.
3. Packages listed in a `package.json` but not imported anywhere in that package.
4. Imports of packages that are not declared as a dependency of the importing

For each finding give the package path and the specific dependency. Suggest the
concrete `package.json` change. Do not run any install or modify any lockfile.
```

```yaml
name: Claude — manual prompt runner

on:
  workflow_dispatch:
    inputs:
      prompt_file:
        description: "Saved prompt to run (ignored if free-text prompt is filled in)"
        required: true
        type: choice
        default: code-review.md
        options:
          - code-review.md
          - security-audit.md
          - i18n-drift.md
          - dependency-audit.md
          - test-coverage-gaps.md
      prompt:
        description: "Free-text prompt — overrides the saved prompt above when non-empty"
        required: false
        type: string
        default: ""
      model:
        description: "Model to run with"
        required: true
        type: choice
        default: sonnet
        options:
          - sonnet
          - opus
          - haiku
      scope:
        description: "Optional path to focus on, e.g. apps/web"
        required: false
        type: string
        default: ""

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  run-prompt:
    name: Run prompt
    runs-on: ubuntu-latest
    timeout-minutes: 30
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
    steps:
      - name: Checkout
        uses: actions/checkout@v6
        with:
          fetch-depth: 0

      # Inputs are bound to env rather than interpolated into the script body.
      # Interpolating ${{ inputs.prompt }} directly into run: would let prompt
      # text terminate the shell command and execute arbitrary code.
      - name: Resolve prompt
        id: resolve
        env:
          FREE_TEXT: ${{ inputs.prompt }}
          PROMPT_FILE: ${{ inputs.prompt_file }}
          SCOPE: ${{ inputs.scope }}
        run: |
          set -euo pipefail

          if [ -n "${FREE_TEXT}" ]; then
            SOURCE="free-text"
            BODY="${FREE_TEXT}"
          else
            SOURCE=".github/prompts/${PROMPT_FILE}"
            if [ ! -f "${SOURCE}" ]; then
              echo "::error::Prompt file not found: ${SOURCE}"
              exit 1
            fi
            BODY="$(cat "${SOURCE}")"
          fi

          echo "Prompt source: ${SOURCE}"

          {
            echo "body<<CLAUDE_PROMPT_EOF"
            echo "REPO: ${GITHUB_REPOSITORY}"
            echo "BRANCH: ${GITHUB_REF_NAME}"
            if [ -n "${SCOPE}" ]; then
              echo "SCOPE: restrict your analysis to the path '${SCOPE}'"
            fi
            echo ""
            echo "${BODY}"
            echo "CLAUDE_PROMPT_EOF"
          } >> "${GITHUB_OUTPUT}"

      - name: Run Claude
        uses: anthropics/claude-code-action@v1
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          prompt: ${{ steps.resolve.outputs.body }}
          claude_args: --model ${{ inputs.model }} --max-turns 30
```

```yaml
name: Claude — @claude mention

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]
  pull_request_review:
    types: [submitted]
  issues:
    types: [opened, assigned]

concurrency:
  group: ${{ github.workflow }}-${{ github.event.issue.number || github.event.pull_request.number }}
  cancel-in-progress: false

jobs:
  respond:
    name: Respond to mention
    runs-on: ubuntu-latest
    timeout-minutes: 30
    # The action detects its own trigger phrase, but gating here avoids starting a
    # runner for every unrelated comment in the repository.
    if: |
      contains(github.event.comment.body, '@claude') ||
      contains(github.event.review.body, '@claude') ||
      contains(github.event.issue.body, '@claude')
    permissions:
      contents: write
      pull-requests: write
      issues: write
      id-token: write
    steps:
      - name: Checkout
        uses: actions/checkout@v6
        with:
          fetch-depth: 0

      - name: Run Claude
        uses: anthropics/claude-code-action@v1
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          trigger_phrase: "@claude"
          claude_args: --model sonnet --max-turns 30
```

Note `cancel-in-progress: false` here, unlike the other workflows. Two people can mention Claude on the same issue in quick succession, and cancelling the first response mid-write would leave a half-written comment.

```yaml
name: Claude — automatic PR review

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]

concurrency:
  group: ${{ github.workflow }}-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  review:
    name: Review pull request
    runs-on: ubuntu-latest
    timeout-minutes: 20
    if: github.event.pull_request.draft == false
    # No contents: write. This workflow fires automatically, including on commits
    # Claude itself just pushed via the dispatch workflow. Comment-only is enforced
    # twice: here, and again by the --allowedTools list below.
    permissions:
      contents: read
      pull-requests: write
      id-token: write
    steps:
      - name: Checkout
        uses: actions/checkout@v6
        with:
          fetch-depth: 1

      - name: Review
        uses: anthropics/claude-code-action@v1
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          track_progress: true
          use_sticky_comment: true
          prompt: |
            REPO: ${{ github.repository }}
            PR NUMBER: ${{ github.event.pull_request.number }}

            Review this pull request against the conventions in AGENTS.md:
            camelCase for variables and functions, PascalCase for components and
            types, strict TypeScript, oxlint via .oxlintrc.json, oxfmt formatting,
            MobX stores in packages/shared-state.

            Focus on, in order:

            1. Correctness — logic errors, unhandled edge cases, wrong async handling.
            2. Security — injection, auth gaps, unsafe rendering of user input.
            3. Error handling — try/catch with proper error types.
            4. Consistency — divergence from patterns in the surrounding package.

            Use inline comments for specific line-level issues. Use one top-level
            comment for general observations.

            Be concise and concrete. If the diff is small and clean, say so in one
            or two sentences rather than manufacturing feedback.
          claude_args: |
            --allowedTools "mcp__github_inline_comment__create_inline_comment,Bash(gh pr comment:*),Bash(gh pr diff:*),Bash(gh pr view:*),Read,Grep,Glob"
```

# Workflows

This fork adds four workflows alongside the nine inherited from `makeplane/plane`.
The inherited files are untouched; anything below is fork-local.

## Added by this fork

| File | Trigger | Claude can write? |
|---|---|---|
| `ci.yml` | PR into `preview`, or manual dispatch | n/a |
| `claude-dispatch.yml` | Manual dispatch | Yes |

Permissions are scoped by how deliberate the trigger is. Dispatch and mention are
explicit human actions, so they get `contents: write`. The automatic PR review does
not, because it fires unattended — including on commits Claude itself just pushed.

## Running a prompt

From the Actions tab, choose **Claude — manual prompt runner**, then **Run workflow**.

- **prompt_file** — pick a saved prompt from `.github/prompts/`.
- **prompt** — free text. When non-empty this wins and `prompt_file` is ignored.
- **model** — `sonnet` (default), `opus`, or `haiku`.
- **scope** — optional path such as `apps/web` to narrow the analysis.

From the CLI:

```bash
gh workflow run claude-dispatch.yml --ref feat/workshop \
  -f prompt_file=security-audit.md \
  -f model=sonnet \
  -f scope=apps/api
```

## Prompt library

| File | Purpose |
|---|---|
| `code-review.md` | General code quality review |
| `security-audit.md` | Injection, auth, secrets, unsafe rendering |
| `i18n-drift.md` | Locale key drift in `packages/i18n` |
| `dependency-audit.md` | Catalog bypasses, version skew, phantom deps |
| `test-coverage-gaps.md` | Highest-risk missing tests |

Adding a prompt takes two edits: create the file in `.github/prompts/`, then add its
filename to the `options:` list of the `prompt_file` input in `claude-dispatch.yml`.
GitHub Actions `choice` inputs are static and cannot enumerate a directory, so the
dropdown must be maintained by hand. The file is the source of truth; the dropdown is
only a menu.

## Auth

All Claude workflows authenticate with the `CLAUDE_CODE_OAUTH_TOKEN` repo secret,
which is generated by `claude setup-token` and backed by a Claude subscription rather
than per-token API billing. Rotate it with:

```bash
claude setup-token
gh secret set CLAUDE_CODE_OAUTH_TOKEN
```

## Known limits

- Pull requests opened from a different fork do not receive repository secrets, so
  `claude-review.yml` will not run Claude on them.
- `ci.yml` uses `turbo --affected`, which needs a PR base to diff against. On manual
  dispatch there is no base, so it checks the entire monorepo and takes far longer.
- There is no scheduled workflow. Claude runs only when explicitly invoked.
